# 课程表 App（Android / vivo 橘子系统 OriginOS）

把课表 PDF 变成一个原生安卓应用：

- **多学校导入，课表随文件变化** —— 导入时先选学校，再选文件；每所学校有自己的读表方案：

  | 学校 | 文件 | 读表方式 |
  | --- | --- | --- |
  | 沈阳师范大学 | 教务 PDF | 手写 PDF 解析（按字体解码、按竖直空隙切卡片、续表合并） |
| 沈阳航空航天大学 | 教务 PDF | 版式与沈师大一致，共用同一套 PDF 解析 |
| 东北财经大学 | 教务 PDF | 同上（**需文字版 PDF**；截图/扫描的 PDF 读不出，会提示改用 Excel） |
  | 沈阳工程学院 | 教务导出的 .xls | 自带 BIFF8 读取器（OLE2 + 共享字符串 + 合并单元格），按"大节 × 星期"网格取值 |

  沈阳工程学院的**作息时间直接取自文件**（每行都写着 `08:20-10:00`），导入后自动替换 App 里的节次时间；
  课表只排周一到周五时，周视图也相应只显示 5 列。
- **像日程表一样显示** —— 周视图（左列节次时间 × 右侧周一到周日网格）+ 日视图（按节次列出当天课程）。
  - 列宽**按屏幕宽度自适应**：时间列 = 屏宽 × 11.5%（26–40dp），其余均分给 7 天，
    所以 320–430dp 的常见手机都能**一屏看全周一到周日**，不用左右滑；
    只有屏幕窄到日列不足 34dp 时才退化为横向滚动。
  - 纵向同样自适应：可用高度均分给各节次，表格正好填满屏幕，底部不留空白；
    屏幕太矮时退回最小行高并可上下滚动。
  - 顶栏「‹ 第 N 周 ›」两侧箭头与右侧功能图标之间有分隔线；
    **点周次文字即可回到本周**（不在本周时文字变主题色），设置页里也有同一入口。
  - 「现在」红线只画在**今天那一列**内；上课时线在该节课的行内推进，
    **课间停在两节课的接缝上**（课表里课与课之间没有空隙，接缝就是最干净的位置，
    线不会压进下一门课的内容里）；第一节课之前、最后一节下课之后不显示。
- **和手机日程提醒联动** —— 一键把整学期每一节课写成系统日历里的一条日程，并自动挂上「提前 10 分钟」提醒。到点由 vivo 日历/日程弹通知、锁屏显示，**App 不需要常驻后台**。
- **单双周正确区分** —— 「6-16周(双)」展开为第 6、8、10、12、14、16 周；「5-17周(单)」展开为第 5、7…17 周，日历里也只在对应周次生成日程。
- **应用内检查更新** —— 启动即检查，发现新版本弹窗显示版本号与更新内容，可「立即更新」或「下次再说」；
  点更新后转入**后台下载**（前台服务 + 通知栏进度条），可以退出 App，下载完点通知直接安装。
- 首次安装是**空课表**，导入自己的文件后使用；**平时完全离线**，只有「检查更新」会访问 GitHub。仓库里不含任何个人课表数据。

> 已发布到 GitHub：<https://github.com/Leiou1939/BetterTimetable/releases/latest>  
> 发版与更新说明见 **[PUBLISH.md](PUBLISH.md)**。

- **周视图左右滑动切周** —— 在课表上左右划即可看上一周/下一周（也可以用顶栏箭头）。
- **空白表 + 填格** —— 课表始终是 7 天 × 10 节的空白表；导入只是把课程填进对应的格子
  （沈阳工程学院的每个"大节"会展开成两个小节，落在第 1-2、3-4…行）。
- **首次进入引导导入** —— 装好打开就是「还没有课表」，点导入按钮选学校、选文件即可；设置里可以把课表**清空**重来。

## 一、导入自己的课表

应用右上角 **📄 图标**（或 设置 → 导入课表 PDF）→ 选 PDF → 看预览 → 点「导入这张课表」。

解析器读的是 PDF 本身的结构，不依赖固定模板：

| 解析步骤 | 做法 |
| --- | --- |
| 页面/对象 | 扫描 `N 0 obj` 建立对象表（不依赖 xref，损坏的文件也能读），解压 FlateDecode 流 |
| 文字 | 按每个字体的 `/Encoding` 解码，`UniGB-UCS2-H` 等 CID 字体直接按 UTF-16BE 还原，**不依赖 ToUnicode 表**（这类表经常缺失） |
| 列 | 用「星期一…星期日」表头定位 7 列，用单元格边框线确定左右边界 |
| 行 | **每张卡片自带 `(x-y节)` 标记**，节次直接读卡片文本；「节次」栏的数字只用于确认版面 |
| 课程块 | 同一列内按**页内行距**切块（行距 12pt），再在「第二个节次标记」处二次切分——两页续表间距只有 ~15pt，靠间距会把两张卡粘在一起 |
| 续页 | 续表会重画网格，上一页卡片的详情尾部会在续页顶部露出一小段（只有 `字段:值`、没有节次标记）；识别后并回原卡片，不当作新课程 |
| 字段 | 用 `场地:`/`教师:`/`学分:` 等字段名当锚点抽段，把跨行、跨页断开的碎片拼回原值；数值字段取最后一个匹配，避免吃到上一门课的值 |

导入后会先弹预览，逐门列出星期/节次/周次/场地/教师让你确认，再替换课表。

> 解析在后台线程执行，几十毫秒完成；失败会明确提示原因（例如选了非课表 PDF）。

## 二、APK 已经编译好了，直接装

用 JDK 17 + Android SDK 34 + Gradle 8.9 **在本机真实编译并校验通过**，文件在工作目录下：

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `课程表.apk` | 9.7 MB | **装这个**。release 构建（未开混淆），包名 `com.liangyuchen.timetable`，v1.1.1 |
| `课程表-debug版.apk` | 14.9 MB | 完全同功能的调试版；万一 release 装不上就用它 |

两者都能直接安装：`apksigner` 校验 **Verifies**，APK Signature Scheme v2 签名，minSdk 26（Android 8.0）/ targetSdk 34。

> ⚠️ **v1.1.0 起更换了签名密钥**（改用工程内的 `keystore/debug.keystore`，原因见第三节），
> 与 v1.0.0 不是同一张证书。**从 v1.0.0 升级必须先卸载旧版本**，否则会报签名冲突；
> v1.1.0 → v1.1.1 同证书，可直接覆盖安装。
> 卸载会清掉 App 内的设置；日历里已写入的 `[课程表]` 日程不受影响，重新同步会先删后写。

### 装到手机上

1. 把 `课程表.apk` 传到手机（微信文件传输助手 / QQ / 数据线都行）。
2. 手机点开 APK，若提示「不允许安装未知应用」，按提示给「文件管理」或「微信」开启**安装未知应用**权限，再装。
3. vivo 可能会提示风险（因为不是应用商店下载的），选**继续安装**。

> 安装后如果提示签名冲突（之前装过别的版本，尤其是 v1.0.0），先在设置里卸载旧版本再装。
> 导入 PDF 需要能访问「文件」，首次选择文件时系统会要这个权限。

## 三、以后想自己重新编译

工程已经带好 Gradle Wrapper，三条路任选：

### A. 本地编译（已在本机验证可用）

装 **JDK 17** 与 **Android SDK（platform-tools / platforms;android-34 / build-tools;34.0.0）**，然后在工程根目录：

```bat
set JAVA_HOME=D:\path\to\jdk-17
set ANDROID_HOME=D:\path\to\android-sdk
gradlew.bat clean assembleDebug assembleRelease
```

产物：`app\build\outputs\apk\release\app-release.apk` 与 `...\debug\app-debug.apk`。
（`gradlew.bat` 会自动从镜像下载 Gradle 8.9；如需换回官方源，改 `gradle/wrapper/gradle-wrapper.properties` 里的 `distributionUrl`。）

> **调试签名在工程内**：`keystore/debug.keystore`（口令 `android`，别名 `androiddebugkey`）。
> 不用系统默认的 `~/.android/debug.keystore`，是因为在受限环境（文件沙箱、只读用户目录、
> 容器）里 Gradle 写不了它的 `.lock` 文件，`validateSigningDebug` 会直接失败，连
> `assembleDebug` 都跑不起来。该文件已被 `.gitignore` 的 `*.keystore` 排除。
>
> 若只想出 release 包，用 `gradlew.bat clean assembleRelease` 即可；release 未提供
> `TIMETABLE_STORE_FILE` 时会回退到这张本地调试证书。


### B. Android Studio

`File → Open` 打开 `timetable-app` 目录，等 Gradle 同步完成，点绿色 ▶ 或 `Build → Build APK(s)`。

### C. GitHub Actions 云端编译（不用装任何环境）

把 `timetable-app` 里的内容推到 GitHub 仓库（Private 也行），**Actions** 标签里会自动跑 **Build APK**，3～6 分钟后在 Artifacts 里下载 `timetable-apk`。

> 想改课表内容或作息，改完重新编译即可，数据文件见第六节。

## 四、在 OriginOS 上让提醒真正弹出来（重要）

装好后第一次点右上角的「同步」图标，会依次弹出两个权限：

1. **访问日历 / 添加或修改日程** → 选**允许**。（没有它无法写入日历，这是系统限制，任何课表 App 都一样。）
2. **发送通知** → 允许。

然后按下面检查一遍，vivo 对日历提醒管得比较严：

| 位置 | 要设置成 |
| --- | --- |
| 设置 → 应用 → 应用管理 → 课程表 → 权限 | 「日历」和「通知」都是**允许** |
| i管家 / 设置 → 电池 → 后台高耗电 | 允许「课程表」后台运行（其实同步完就不需要它了，可不开） |
| 日历 App → 右上角「⋮」/ 设置 → 日程提醒 | 提醒方式勾上**通知**，不要只留「铃声」；开启「日程默认提醒」 |
| 设置 → 通知与状态栏 → 课程表 | 允许通知、锁屏显示、横幅 |
| 日历 App 里查看 | 应该能看到一堆标题以 `[课程表]` 开头的日程 |

如果手机上有多个日历（vivo 账号日历、本地日历、QQ 邮箱日历…），同步时会让你**选一个**写入。
建议选你在日历 App 里默认显示的那个：

- 选择框里会标出「上次使用」「只读」「**未在日历中显示**」——
  如果某个日历被标成"未在日历中显示"，写进去在日历 App 里是看不到的，别选它。
- 选过一次后 App 会**记住**这个日历，以后点「同步」图标就一键重同步（不会再弹选择框）；
  想换日历，在同步完成后的提示条上点「换日历」。

**每次同步会重新生成「今天起一年内」的全部课程日程**，所以：
- 段考、放假调课后想更新，直接再点一次同步即可；
- 想清空，在 设置 → 「清空本 App 写入的日程」。

### 同步是怎么和提醒联动的（排查时看这里）

| 环节 | 做法 | 之前踩过的坑 |
| --- | --- | --- |
| 认领自己写的日程 | `CUSTOM_APP_PACKAGE` + `CUSTOM_APP_URI` | 原来用 `EVENT_COLOR_KEY` 当标记，部分机型会拒绝/覆盖，导致"下次同步删不掉旧日程 → 越同步越多" |
| 日程状态 | 显式写 `STATUS_CONFIRMED` | 不写时默认是「待定」，某些日历会淡化甚至不显示 |
| 提醒 | 先 `METHOD_ALERT`，失败回退 `METHOD_DEFAULT`，并统计成功条数 | 原来插入失败被静默吞掉，结果**日程有了但一条提醒都没有** |
| 写后校验 | 写完回查一次条数 | 只报"成功"但实际没落库时无法发现 |

同步完成后的提示会明确写出：**写入了多少条、其中多少条带提醒、提前几分钟、写入范围**；
如果该日历不允许自定义提醒，会提示"已改为日历默认提醒"。

### 兜底方案：导入 .ics

如果你的机型日历不读取第三方写入的日历账户（个别定制系统会这样），用导出：

课程详情弹窗 → **导出** → 选「保存到文件」或「发送给…」，把 `课程表.ics` 发给 vivo 日历/系统日历打开导入即可，里面每条日程同样带提前提醒。

## 五、导入之后建议核对两件事

### 1. 开学第一周的周一

课表上只写周次，具体日期由「第 1 周周一是哪天」推出来。默认值是一个占位日期，
导入后请到 **设置 → 开学第一周（周一）** 选成你学校真实的开学日，日历同步的日期才会对。

### 2. 作息时间

- **沈阳工程学院**：时间直接来自 `.xls` 里每行的「第 X 大节 08:20-10:00」，导入即用。
- **沈阳师范大学**：PDF 里不含时间，导入后请到 **设置 → 作息时间** 按学校作息逐节填写；
  改完再同步一次，日历里的日程时间会跟着变。

## 六、课表内容

仓库里**不附带任何个人课表**。安装后是空表，导入自己的 PDF / Excel 即可；
解析结果只保存在手机本机的 SharedPreferences 里，不会上传。

解析器有回归脚本（`tools/run_parser_test.bat <pdf> --check`、`tools/run_sie_test.bat <xls>`），
用来校验星期/节次/课程名/场地/教师，以及单双周与多段周次的展开。

## 七、改课表数据

两种方式：**① 直接导入新的课表 PDF**（推荐，见第一节）；**② 改内置 JSON**——所有课程都在这一个文件里，纯 JSON，改完重新编译即可：

```
app/src/main/assets/course_data.json
```

> 随包发布的 `course_data.json` 只是**空模板**（没有任何课程），
> 导入你的课表后，数据只存在手机本机的 SharedPreferences 里。

一段课程的写法：

```json
{
  "id": "0-1-示例课程",
  "name": "示例课程",
  "teacher": "示例教师",
  "room": "示例教室",
  "day": 0,
  "periodFrom": 1,
  "periodTo": 2,
  "weeks": [1, 2, 3]
}
```

> 也可以在 App 里点「设置 → 恢复内置课表」把开学日期和作息时间改回内置默认值。
> ⚠️ 这个按钮是**整体重置**：开学日期会回到 2026-08-31、作息回到上面那张表，
> 但**课程内容不受影响**（仍是当前这份课表，不会退回 PDF 原始解析结果）。
> 从 v1.1.0 升级上来的用户点一次它，就能拿到 v1.1.1 的新作息时间。

### 技术要点

- **PDF 解析零依赖**：自己实现对象扫描 + FlateDecode（`java.util.zip.Inflater`）+ 字体编码解码，
  不引入 pdfbox 之类的库（省 ~15MB，也避免其 CID 字体兼容问题）。约 700 行 Kotlin。
- 解析器用**真 PDF 在 JVM 上验证**过（`tools/run_parser_test.bat` + `tools/jvmtest/ParserCli.kt`），
  对这份 PDF 输出 18 门课程（含第 2 页续表），字段与人工核对一致；`--check` 模式会逐门断言，
  并单独断言单双周展开与多段周次（`10-11周,13-15周`）的结果。
- `tools/verify_asset.py` 另外检查 `assets/course_data.json` 与解析器**实时输出**逐字段一致
  （两者是同一套代码路径，见 `tools/sync_asset_from_parser.py`）。
- 实测构建环境：Microsoft OpenJDK 17.0.13、Android SDK Platform 34、Build-Tools 34.0.0、Gradle 8.9、AGP 8.5.2、Kotlin 1.9.24、Compose BOM 2024.06.00。
- `minSdk 26`（Android 8.0）→ `targetSdk 34`，OriginOS 3/4/5 都能装。
- 日历写入用标准 `CalendarContract`：`Events` 表插 `DTSTART/DTEND/EVENT_TIMEZONE`，`Reminders` 表插 `MINUTES=10, METHOD=ALERT`。
- 本 App 写入的日程用 `EVENT_COLOR_KEY="[课程表]"` 打标，再次同步时先按标记删除，所以反复同步不会产生重复日程。
- 签名：minSdk ≥ 24 时 AGP 只做 APK Signature Scheme v2（Android 7.0+ 均支持 v2-only），`apksigner verify` 通过。
- 提醒交给系统日历，App 用完即走，不申请自启动、不常驻后台，省电。
